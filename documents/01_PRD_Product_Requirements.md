# PRD — Product Requirements Document

## 1. Продукт

Рабочее название: **Developer Training System (DTS)**.

Это персональная adaptive learning system для подготовки разработчика к первой коммерческой позиции и последующему переходу на Middle.

## 2. Пользователь

Основной пользователь: один разработчик, который:

- имеет неполный практический опыт;
- имеет существующий SaaS/pet-project;
- использовал AI при создании проекта;
- должен самостоятельно восстановить понимание кода и архитектуры;
- хочет заниматься ежедневно;
- хочет получать измеримый прогресс и объективную оценку готовности к собеседованиям.

## 3. Основные продуктовые цели

### G1 — ежедневная регулярность

Пользователь должен получать одно понятное обязательное действие на текущий день и минимум одну короткую сессию recall.

### G2 — долговременное знание

Материал должен возвращаться через адаптивные интервалы и проверяться преимущественно активным воспроизведением.

### G3 — доказуемая компетентность

Знание считается освоенным не после прочтения материала, а после выполнения контрольных заданий без подсказки.

### G4 — понимание собственного SaaS

Система должна проверять архитектуру, data flow, кодовые точки, БД, auth, backend, deployment и способность вносить изменения.

### G5 — контроль AI-зависимости

Система должна различать результат, полученный самостоятельно, и результат, полученный через AI.

### G6 — market readiness

Должен существовать отдельный readiness score для technical screening, coding interview, system design и explanation.

## 4. Ключевые метрики продукта

- Daily Adherence — доля выполненных обязательных дневных сессий.
- Retention — доля правильно воспроизведенных элементов памяти в контрольный срок.
- Independent Coding — доля задач, выполненных без AI.
- Project Understanding — подтвержденное понимание собственного SaaS.
- Interview Readiness — результат mock interviews.
- Middle Gate — прохождение всех обязательных компетенций выше порогов.

## 5. Принципы

1. Не измерять только потраченное время.
2. Не использовать streak как главный показатель.
3. Не объявлять тему «знанием» после просмотра.
4. Ошибка должна порождать действие: повторение, новую задачу, объяснение или debugging.
5. Нельзя компенсировать критическую слабость высоким средним баллом.
6. Новый материал ограничивается пропускной способностью памяти и текущими пробелами.
7. AI используется как инструмент, но readiness оценивается без AI.

## 6. MVP

В MVP входят:

- Telegram bot;
- ежедневная сессия;
- recall queue;
- теория + coding task + explanation task;
- skill map;
- попытки и оценки;
- проектный аудит;
- dashboard;
- AI grading через абстрактный AI gateway;
- недельный контроль;
- Middle Gate v1.

Не входит в MVP:

- полноценный job board aggregator;
- автоматическая отправка откликов;
- платёжная система;
- multi-tenant продукт;
- мобильное приложение;
- fine-tuning собственных моделей.
